中堅企業（複数子会社を抱えるホールディングス等）向けの資金可視化システム（AI-CFO）について、仕様駆動開発（SDD）のベースとなる仕様書（`spec.md`）のたたき台を作成しました。

このファイルをそのままプロジェクトの `specs/spec.md` や `README.md` として配置し、AIエージェントへの指示や開発の基準（Single Source of Truth）として活用できます。

# 仕様書: グループ資金可視化システム (AI-CFO)

**バージョン:** 0.1.0

**作成日:** 2026-08-03

**ステータス:** Draft (たたき台)

---

## 1. システム概要と目的

### 1.1 背景と目的

複数子会社を傘下に持つ中堅ホールディングス・グループ企業において、子会社ごとの会計ソフト・銀行口座の分散により「グループ全体の現預金残高」「未来の資金繰り」の把握に膨大な工数がかかっている。

本システムは、異種フォーマットの取引データを取り込み、AIを活用して**未来の資金繰り予測・リアルタイム可視化・資金リスクの自動検知**を低コストかつ即効性をもって実現することを目的とする。

### 1.2 コアバリュー

* **即効性**: 各種会計ソフトのCSV/仕訳データをドラッグ＆ドロップするだけで統合。
* **未来予測**: 過去の入出金サイクルと今後の請求・支払予定から、30〜90日後のキャッシュ残高をAIが予測。
* **リスク検知**: 資金ショートの兆候や子会社間の余剰資金を特定し、改善策（グループ内融資等）を提案。

---

## 2. システム構成と技術スタック (アーキテクチャ)

* **フロントエンド**: Next.js (App Router) / TypeScript / Tailwind CSS / Tremor (ダッシュボード用UI)
* **バックエンド**: Python (FastAPI) または Node.js (API Route)
* **データベース**: Supabase (PostgreSQL) ※行レベルセキュリティ (RLS) によるマルチテナント/子会社間アクセス制御
* **AI・分析エンジン**: LLM API (Gemini / Claude 等) + 時系列解析ロジック
* **デプロイ・インフラ**: Vercel + Supabase

---

## 3. ドメインモデル & データ構造仕様

### 3.1 統合データモデル (`specs/schema.prisma` 相当)

#### `Company`（企業・子会社情報）

* `id` (UUID): 企業ID
* `name` (String): 企業名
* `parent_id` (UUID, nullable): 親会社ID

#### `CashAccount`（口座情報）

* `id` (UUID): 口座ID
* `company_id` (UUID): 所属企業ID
* `bank_name` (String): 銀行名
* `account_number` (String): 口座番号（暗号化）
* `current_balance` (Decimal): 現在残高
* `currency` (Enum): JPY, USD等

#### `Transaction`（明細・予実データ）

* `id` (UUID): 取引ID
* `company_id` (UUID): 子会社ID
* `transaction_date` (Date): 取引日（または発生予定日）
* `amount` (Decimal): 金額（正: 入金、負: 出金）
* `category` (String): 勘定科目・区分（売掛回収、買掛支払、給与、税金等）
* `status` (Enum): `ACTUAL`（実績）, `EXPECTED`（予定）
* `partner_name` (String, nullable): 取引先名称

#### `CashForecast`（AI予測キャッシュデータ）

* `id` (UUID)
* `company_id` (UUID)
* `forecast_date` (Date): 予測対象日
* `predicted_balance` (Decimal): 予測残高
* `risk_level` (Enum): `SAFE`, `WARNING`, `CRITICAL`
* `ai_comment` (Text): AIによる注記・コメント

## 4. 機能要件

### F-1: マルチフォーマット・データインポーター

* **要件**: freee、マネーフォワード、勘定奉行、Excel等から出力されたCSVを自動認識・マッピングしてDBへ登録。
* **仕様**:
1. ユーザーがCSVをアップロード。
2. AI/パーサーがヘッダー行を解析し、`date`, `amount`, `category`, `partner_name` に自動マッピング。
3. 未登録の勘定科目は「標準カテゴリ」に自動分類。



### F-2: グループ合成資金ダッシュボード

* **要件**: 親会社経営陣がグループ全体の現預金推移を一目で把握可能。
* **仕様**:
* グループ全社の「本日時点の合計現預金残高」を表示。
* 子会社ごとの残高シェア（パイチャート）および今後3ヶ月の合成キャッシュフロー推移（折れ線グラフ）。
* フィルタリング機能（子会社単体 / グループ全社 / 特定期間）。



### F-3: AI資金繰り予測＆ショートアラート Engine

* **要件**: 過去のパターンと予定データから未来の残高を算出し、アラートを発行。
* **仕様**:
* **予測ロジック**: 確定済みの予定データ（`EXPECTED`）＋過去12ヶ月の不定期支出・入金遅延傾向をAIで補正して算出。
* **アラート条件**: 設定した最低維持残高（例: 月間固定費の1ヶ月分）を今後90日以内に下回る確率が70%以上の場合、ダッシュボード上に警告を表示。



### F-4: グループ内資金最適化アドバイザー (社内融資提案)

* **要件**: 余剰資金のある子会社から、不足が見込まれる子会社への資金移動案を提示。
* **仕様**:
* AIが全社予測をスキャンし、「A社の余剰資金（〇〇万円）をB社へ融資することで、B社の資金ショートと銀行短期借入コストを回避可能」といった提案文を自動生成。

## 5. 画面・UI設計要件 (UI/UX Spec)

1. **メインダッシュボード (`/dashboard`)**
* トップ: グループ合計残高・今月の着地予測・危険アラート通知欄
* メイングラフ: 過去3ヶ月の実績 ＋ 未来3ヶ月のAI予測推移
* サブパネル: 子会社別残高ランキング & 資金効率（ROIC/回転率）


2. **データ取り込み画面 (`/import`)**
* ドラッグ＆ドロップ領域
* マッピング確認プレビュー（AI推測結果の補正インターフェース）


3. **AIアドバイザリー画面 (`/insights`)**
* AIによる資金繰りレポート（毎週/毎月自動更新）
* 子会社間資金融通のシミュレーションツール



---

## 6. 非機能要件 & セキュリティ

* **セキュリティ**: 財務データを扱うため、Supabaseの Row Level Security (RLS) を活用し、他社・許可されていない子会社のデータを厳格に隔離。
* **データ保持**: 過去データは最低5年間保持し、時系列解析に利用。
* **処理速度**: 10,000件のCSVデータ取り込み・AI解析を30秒以内に完了すること。
